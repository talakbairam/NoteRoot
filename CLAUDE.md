## What it is

VS Code extension (TypeScript, esbuild; no runtime dependencies). The user picks one root folder (`noteRoot.rootPath`). The sidebar has a **Notes** tree (Explorer-like) and a **Quick Note** webview that appends text to one file. Notes are plain files. No telemetry. The network is used by the optional **Sync** (below; GitHub is the first service), only when the user presses one of its buttons, with the same rule for the optional **Google Drive sync** (below; Google sign-in in the browser, then the Drive API). License: GPL-3.0.

## Commands to run

- `npm run lint` and `npm run compile` (type check, lint, bundle) must both finish with zero errors and zero warnings. `npm run format` (Prettier, dev dependency, rules in `.prettierrc`) formats `src`; run it before finishing.
- F5 starts the Extension Development Host. You cannot run F5 from here, so say so when UI behaviour is unverified.

## Hard rules

1. Strict TypeScript. No `any` unless unavoidable and commented.
2. All file access through `vscode.workspace.fs` and `Uri`. Never Node `fs` (Remote support).
3. Services (`src/services`) never show UI. They throw typed errors (`src/util/errors.ts`) or take callbacks. Commands and UI decide what the user sees.
4. All user-facing text in `src/constants/strings.ts`. Command IDs, setting keys, context keys in their own constants files.
5. No runtime dependencies. Dev dependencies only. Node's `node:crypto` and the global `fetch` are enough for everything (encryption, GitHub, Google).
6. Never delete or overwrite silently. Delete goes to the Trash, and permanent delete needs its own explicit question.
7. Every path-changing operation is checked with `PathGuard` (inside the root, segment-wise, OS case rules).
8. Dispose everything through `context.subscriptions`.
9. Catch errors at command boundaries: `registerSafeCommand` logs details and shows one friendly message.
10. Webview: strict CSP with nonce, theme colour variables only, validate every incoming message.
11. Never log note contents. Log relative paths and metadata only.

## Behaviour digest

- **Root states** (`noteRoot.state`): `noRoot`, `missing`, `empty`, `ready`. Drive the `viewsWelcome`. `noteRoot.hasRoot` is true for `empty` and `ready`. `RootFolderService` also owns a debounced (250 ms) watcher and re-checks when the window regains focus.
- **Config** `.noteroot/config.json`: created if missing, never overwritten. Corrupt or unreadable: keep working with defaults, warn once with "Open Config File", leave the file alone. Newer `schemaVersion`: do not modify.
- **Tree**: folders first, natural case-insensitive sort, lazy loading (`readDirectory` only), file icon theme through `resourceUri` (no `iconPath`), `id` = relative path, tooltip via `resolveTreeItem`, directory symlinks shown but never expanded. Context values: `noteRoot.folder`, `noteRoot.file`, `noteRoot.file.md`, `.quickNote` suffix for the Quick Note file.
- **Sort order** (`noteRoot.sortOrder`, `name` or `modified`, command `noteRoot.sortBy` in the Command Palette, and the row **Sort notes by** of the Settings page; it is no longer in the `...` menu of the Notes view): folders first in both. `modified` is newest first and stats every entry of the folder being read (the only case where `getChildren` does more than `readDirectory`); equal times fall back to the name. The setting is written Global by `SettingsService.setSortOrder` and the tree refreshes on change. Recent, Pinned and search are not affected.
- **Opening**: single click preview, double click permanent (`DoubleClickTracker`, 400 ms). Large-file confirmation. Falls back to `env.openExternal`.
- **Duplicate** (`noteRoot.duplicate`, context menu of files and folders): `FileOperationsService.duplicate` copies with `workspace.fs.copy(..., { overwrite: false })` (recursive for folders) next to the original. The name comes from the pure `duplicateName` (`name copy.ext`, `name copy 2.ext`, ..., first name no sibling has, case-insensitive; a leading dot is not an extension) and goes through `prepareNewEntry` (validation and PathGuard). Symbolic links to folders are not offered.
- **Create/rename/delete**: names validated for every OS and compared case-insensitively. Rename uses `WorkspaceEdit.renameFile`. Case-only rename allowed. Quick Note file (or a folder containing it) warns on rename, move and delete.
- **Undo** (`noteRoot.undo`, Ctrl/Cmd+Z when `focusedView == noteRoot.tree`, palette, `...` menu): `FileOperationsService` keeps the last `MAX_UNDO_STEPS` (20) renames and moves in memory as steps of `{ from, to }` pairs (`rename` and `moveItems` record them; one drag = one step). `undoLast` pops the latest step and moves every item back, last first, through `renameKeepingEditors`. It never overwrites: an item that is gone, whose old name is taken (case-insensitive, except the item itself in a case-only rename) or whose old folder is gone is reported in `failed` and left alone, and the step is dropped anyway. Not undoable: delete (Trash), create, duplicate, import, and a Replace in a move (the replaced item is in the Trash). History is cleared on a root change.
- **Drag and drop**: multi-select, folder/file/empty-area targets, no folder into itself, nested items dropped, conflicts ask Replace/Skip/Cancel (Replace trashes the old item first).
- **Advanced mode** (Quick Note): `AdvancedModeService` keeps the on/off state in `globalState` (`noteRoot.advancedMode`) and publishes it as the context key `noteRoot.advanced`. A title bar button (`navigation@2`, the only icon button of the view, the same `$(settings)` sliders icon in both states) switches it with two commands, `noteRoot.enableAdvanced` (shown while off) and `noteRoot.disableAdvanced` (shown while on), because a contributed command cannot change its own tooltip. The webview gets `advanced` in `init` and an `advanced` message, and shows `#advanced`: a flex group of two **combo boxes** (`#category-combo`, `#tag-combo`: a text input with `role="combobox"`, a toggle button and a `ul[role=listbox]`), between the textarea and the footer buttons. They are made by `createCombo` in `quickNote.js` (no libraries) and coloured with the `--vscode-input-*`, `--vscode-dropdown-*` and `--vscode-list-*` variables; they sit side by side and stack on a narrow sidebar. A native `<select>` was used before and dropped because it cannot autocomplete. `.advanced[hidden]` must keep `display: none`, because `display: flex` would otherwise override the attribute. The lists are empty in the HTML and filled by `quickNote.js` (`applyLists`) from the lists in `init` and `options` messages. Behaviour of a combo: click, focus or arrow opens the whole list; typing sets `typed` and narrows it (exact, then start-with, then contains, case-insensitive; the first entry is highlighted so Enter takes the best match); the last entry is **Create…** (with the typed text as `name` when it is not a name yet). Options use `mousedown` + `preventDefault`, so the input keeps the focus and `blur` can decide: an emptied category box clears the choice, an exact name (any case) is taken, anything else is undone; the Tag box is always emptied. Escape closes only the list. The open list always stays inside the visible panel (`place()` in `createCombo`: it opens downwards, or upwards when there is more room above, with a maximum height of the room it has, up to 180 px, and scrolls inside itself; `scrollIntoView` is not used because it could move the whole page), so the page never has to be scrolled to reach it. All texts come from `data-*` attributes written by the extension. The chosen category decides the file (see below) and the chosen tags are written with the note (see below); each choice is also remembered by the webview state (`category` as text, `tags` as a list, merged with `draft` through `saveState`).
- **Categories and tags**: `LabelService` stores them in `custom.categories` and `custom.tags` of `<root>/.noteroot/config.json`, so each notes folder has its own. A category is `{ name, file? }` (`file` relative to the root, `/`-separated); older entries that are plain strings are still read, and any other field of an entry is kept when the entry is rewritten. The **Create…** entry of each box makes the webview send `createOption` (with `name` when the user typed one, at most 200 characters, validated in `parseWebviewMessage`); `QuickNoteViewProvider.onCreateOption` asks for the name with an input box (starting with the typed text, `askNewLabel(..., initialName)`; the duplicate check uses only the stored names, not the categories made from files) (validated by `LabelService.validateName`: not empty, at most 50 characters, no control characters, no duplicate in any case). For a category it then asks for the file through the internal command `noteRoot.pickNoteFile` (existing note, new note typed with a suggestion from `LabelService.suggestFileName`, or none; cancelling there cancels the whole creation), calls `LabelService.create` and answers with an `options` message that selects the new name. Writing goes through `ConfigService.updateCustom`: it reads the file again, **refuses (ConfigLockedError) when the file is invalid or has a newer `schemaVersion`**, keeps every unknown field, and serializes writes. Names are shown sorted but stored in creation order. `noteRoot.changeCategoryFile` links an existing category to another file (`LabelService.setCategoryFile`).
- **Notes go to the category file**: the webview reports the category its box shows with `choiceChanged` (only real changes; a name that vanished from the list is reported as empty). `LabelService.setSelectedCategory` keeps the chosen category in memory (the Tag dropdown has its own message, see **Tag in the note**). `QuickNoteService.write` asks `LabelService.getActiveCategoryFile()` (reads the config now, and is `undefined` when the Advanced mode is off, nothing is chosen, or the category has no file) and writes there instead of the Quick Note file. Unlike the Quick Note setting there is **no quiet fallback**: a category file that is not inside the notes folder (for example edited by hand) throws `CategoryFileError` and nothing is written. `QuickNoteService.append` and `appendClipboard` return the relative path they wrote to, which the status bar messages show. For display only (`getTargetPath`, panel title, Save tooltip) the file is cached in `LabelService.activeCategoryFile`, refreshed with `refreshActive()` by `QuickNoteViewProvider.refreshTarget` whenever the choice, the lists, the mode or the folder change.
- **Tags in the note**: any number of tags can be chosen. The **Tag** box in the page does not keep a value: picking a name adds it to `chosenTags` and shows a chip (`#tag` with a × button) in the panel `#tag-chips`, which is always shown while the Advanced mode is on, has a fixed height (32 px at first, one row of chips) that the user changes by dragging its corner, scrolls when the chips do not fit, and says "Chosen tags appear here" while it is empty (`:empty::before` with `data-empty`); `keepResizable(element, key, minPx)` in `quickNote.js` remembers the height of this panel (`tagsHeight`) and of the text box (`height`) in the page state, and the list only offers names that are not chosen yet (`renderTags`, `setChosenTags`; the page state key is `tags`, an older single `tag` is still read). The page reports the list with `tagsChanged` (validated: at most 50 texts, each at most 200 characters), `LabelService.setSelectedTags` keeps it (no repeats, no empty names) and `activeTags` is empty while the Advanced mode is off. `options` messages drop chips whose tag no longer exists and add the `select` tag (a created or renamed one); `rename` and `remove` keep `chosenTags` in step. `QuickNoteService.write` passes `activeTags` to `buildAddition` / `buildStartInsertion` as `tags`; `formatTags` joins `formatTag` results (`#tag`, white space becomes `-`) with a space. The line comes after the heading and a blank line and is followed by a blank line, then the note. No tags gives the line **empty** (`**Tags:** `) when the template has text besides `{tags}` (`tagLine.replace("{tags}", "").trim()` is not empty); a template that is only `{tags}` writes nothing. Run Tagging and Tag when saving fill such a line later (`tagLineMatcher` accepts it). Its text is the template of `noteRoot.quickNoteTagLine` (default `**Tags:** {tags}`; `SettingsService.quickNoteTagLine` falls back to the default for a value that fails `isValidTagLine`: contains `{tags}`, at most 100 characters, one line, no white space at the start or end), with `{tags}` replaced (by a function, so `$` in a tag is safe) by the `#tag` list; `buildBlock` takes it as `tagLine`, default `{tags}` for the pure functions, the service passes the setting. The Quick Note Options list has an entry with presets and **Custom…**. The tag scan and the previews recognise a tag anywhere (`#` at a line start or after white space), so any template works with them.
- **Keywords**: a category or tag may have a `keyword` (stored in its entry in `custom.categories` / `custom.tags`; a tag is an object `{ name, keyword }` only while it has one and goes back to a plain text without it; every other field of an entry is kept). `LabelService.setKeyword` writes it through `ConfigService.updateCustom`, `validateKeyword` checks it (`MIN_KEYWORD_LENGTH` 3 after trimming, at most 50, no control characters, not the keyword of another entry of the same kind, any case; empty removes it), `Labels.tagKeywords` and `Category.keyword` read it. The one rule is `keywordPosition(text, keyword)` / `containsKeyword`: the trimmed keyword appears **anywhere** in the note, case-insensitive, as plain text (no word boundaries). At Save `QuickNoteService.write` asks `LabelService.autoTagsFor(text)` (tags whose keyword the note contains; empty while the Advanced mode is off) and merges them after the chosen chips (`new Set`), and asks `getDestinationFor(text)`: the category chosen in the box wins, otherwise the stored category whose keyword appears **first** in the text (the longer keyword when they start at the same place), with its `file` or the Quick Note file when it has none. The text is never changed. The page gets `tagKeywords` and `categoryKeywords` in `init` and `options` and only **previews** the result with the same rule (faded `.chip.auto` without button, placeholder of the Category box from `data-auto-template`); the extension decides at Save. Set from the Manage list (`keyword` button/menu entry) and from the panel (`noteRoot.setLabelKeyword`), both through `performLabelAction`. Not for the categories made from files. (It was a prefix, "the note starts with", at first; it became a keyword that can be anywhere in the note.)
- **Add Tag Pattern presets** (`askNewPattern` in `tagPatternCommands.ts`): a QuickPick of ready-made kinds, `Prefix and number` (`presetPattern("number", prefix)` = `<prefix>#`), `Prefix and letters` (`@`) and `Prefix and anything` (`*`), then an input box for the prefix only (`isValidPrefix`: letters, digits, `-` and `_`; the resulting pattern still goes through `validateTagPattern`, so at least `MIN_PATTERN_LITERALS` = 2 characters and no duplicate); under a separator "Advanced", `Write the pattern myself…` opens the old input box with the whole syntax. Changing a pattern (`editTagPattern`) always uses the input box with the whole syntax. The pure helpers are in `TagPatterns.ts`.
- **Auto create tag from pattern** (`AutoTagPatternService`: on/off in `globalState` `noteRoot.autoTagPatterns` and the context key of the same name, commands `enableAutoTagPatterns` / `disableAutoTagPatterns` swap in the title bar of the Tags & Categories view like the other switches; the patterns are listed in the panel, group **Tag Patterns** under Tags: `PatternGroupItem` (**collapsed** at first like Tags, because counting needs a scan; description = number of patterns, ` · off` while the mode is off, a `+` inline button = `noteRoot.addTagPattern`) with `PatternItem` rows in the format of the tags and categories (always collapsible so the rows line up, description `N tags`, context value `noteRoot.tagPattern`, menu entries `editTagPattern` and `deleteTagPattern`), opening to `PatternTagItem`s (the distinct texts the pattern matched in notes, `#name`, `N notes`, collapsible) which open to `TagNoteItem`s (id prefix `patnote:<pattern>` so ids never clash with the notes of a stored tag), or to one `PatternEmptyItem` ("No matches yet") when nothing matched. `TagIndexService.scanPatterns(patterns)` makes this in one walk of the notes folder (same limits as the tag scan) with `findPatternMatches` (one pattern: each distinct match, first position) and `positionAt`; the result is kept in the provider (`patternScan`) until `refresh()`, like the scan of the tags; there is no entry in the `...` menu. `noteRoot.manageTagPatterns` (palette only) is the same as a QuickPick loop, all in `tagPatternCommands.ts`): a pattern is text with `*` (`ab-*`), stored as a plain text list in `custom.tagPatterns` of the config file (`LabelService.getTagPatterns`, `saveTagPattern(pattern, replace?)`, `removeTagPattern`, always through `updateCustom`, so a damaged or newer config is refused; hand-written odd entries are ignored). `TagPatterns.ts` is pure: `validateTagPattern` (1 to 50 characters, no white space, no `**`, at least one `*`, at least `MIN_PATTERN_LITERALS` = 2 other characters, no duplicate in any case), `patternToRegExpSource` (flags `giu`; wildcards, each one to `MAX_WILDCARD_RUN` = 100 characters: `*` = `[\p{L}\p{N}_-]`, `#` = `\p{Nd}`, `@` = `\p{L}`, and a list `[abc]` / `[^abc]` (`wildcardClass`: the text between the brackets with `\`, `^` and `[` escaped, so `-` makes ranges; a list of characters that are not allowed also excludes `\s`, and no wildcard matches white space; the flag `i` makes lists case-insensitive too). `tokenizePattern` cuts a pattern into fixed text and wildcards and returns undefined for a `[` or `]` that is left over, `[]`, `[^]` and a list that does not compile (`[z-a]`), which `validateTagPattern` reports as `badList`; a match can **start anywhere** and **ends where its wildcard stops**, there are no word boundaries; a pattern that **starts with a wildcard** gets a lookbehind for that wildcard's characters, otherwise every position of a long word would be tried; the run limit and that lookbehind keep the search linear on a huge note, which a test checks; everything else is escaped, so `#` and `@` cannot be fixed text; `validateTagPattern` refuses two wildcards in a row and counts only the other characters toward `MIN_PATTERN_LITERALS`) and `findPatternTags` (the matched text as written, a `-` or `_` at its end dropped, once each in any case, in order of appearance, at most `MAX_PATTERN_TAGS` = 20). `LabelService.autoTagsFor(text)` adds these after the keyword tags while the mode **and** the Advanced mode are on, and `QuickNoteService.write` merges everything with `uniqueNames` (once each, any case). **The tags are written in the note only, never stored in `custom.tags`** (otherwise the list would fill up with ticket numbers). The page gets the regular expression **sources** (`tagPatterns` in `init` and `options`, empty while the mode is off, from `getTagPatternSources`) and previews with the same sources (`patternTagNames`, faded `.chip.auto`), so the extension and the page cannot disagree; a source that does not compile is skipped.
- **Run Tagging** (`noteRoot.tagNote` in the context menu of Notes tree files, several selected files allowed; `noteRoot.tagCurrentNote` in the palette for the active editor, refuses a file outside the root): `NoteTaggingService.tagNote(uri)` reads the note (the open document, or `SearchService.readText`: a file that is binary or over 1 MB is `skipped`), asks `LabelService.getAutoTagger({ ignoreAdvanced: true, ignorePatternMode: true })` once (lists read once; keyword tags, then pattern tags; **neither the Advanced mode nor the button of the patterns matters, because the user asked**; they only decide what happens by itself at Save) and applies the pure `planNoteTags(existing, tagger, template, eol, headingMatcher)` from `NoteTagging.ts`, which gives a list of replacements `{ offset, deleteLength, insert }` (`applyTagEdits`; the open document gets them all in one `WorkspaceEdit`), `notes`, `changed`, `added` and a kind (`none`, `unchanged`, `updated`, `added`, `entries`). **A file of Quick Notes is tagged entry by entry**: `entryHeadingMatcher(quickNoteTimestampFormat)` builds the regular expression of an entry heading (`YYYY MM DD HH mm ss` become digits, `#`s in front allowed; undefined for an empty format, then the file is one note); each heading starts an entry that runs to the next heading; the entry's tags come from its own text **without its tag line**; its tag line is the first non-blank line below the heading when it matches the template, and is updated with the missing tags, or, when there is none, a new line is inserted below the heading in the Quick Note shape (heading, blank, line, blank, text); an empty entry is skipped; the text before the first heading is one more note (planned like a file without entries, with its own tag line, and counted only when it has more than that line). Any other file is one note and uses `planTagLine`, below. **The tag line at the top** is the first non-blank line after a BOM, a front matter block (`startOfNote`, shared with `buildStartInsertion`) and blank lines, when it matches the tag line template (`quickNoteTagLine` with `{tags}` as `#a #b…`; `tagLineMatcher` also accepts the line **without tags**, such as `**Tags:**` with or without the space after it, when the template has text of its own to recognise it by, so an empty line the user left is filled and no second line is added above it; with the template `{tags}` alone an empty line is only an empty line); it is updated with the wanted tags it lacks (the tags already there stay as written, any case counts as the same, a name with spaces counts as its dashed form) and otherwise a new tag line is **added at the start** of the note (after the front matter, followed by a blank line). A first line that is a heading is not a tag line (a Quick Note file never gets a file-level line from Run Tagging; its entries get theirs). The open document is edited with a `WorkspaceEdit` (saved only when it was clean, like Quick Notes); other files are written with `workspace.fs`. The line ending is the one of the note (`\r\n` when it has one). Not covered: a tag line written with an older template, and a write between the read and the write.
- **Tag when saving** (`noteRoot.tagOnSave`, boolean, **off** by default, `SettingsService.tagOnSave`; a `toggle` row of the Settings page): `NoteTaggingService.start()` registers `workspace.onWillSaveTextDocument`. The listener returns when the setting is off, when `event.reason` is not `Manual` (the automatic save and the save on focus change would write tags while the user types), or when `InternalSaves.isActive(uri)`; otherwise `event.waitUntil(editsForSave(document))`, so the tags are part of that save: no second save, undo takes them away, and VS Code gives the participants about 1.75 s. `InternalSaves` marks the file while NoteRoot itself saves it (`QuickNoteService.appendToOpenDocument` and `NoteTaggingService.tagNote` call `internalSaves.during(uri, () => document.save())`), because a save made by code looks like a manual one. `planOnSave(document)` works only for `file:` documents inside the root that no exclude pattern hides (`isHidden`, every segment), at most 1 000 000 characters; **what is on disk is the text of the last save**, so the changed stretch is `changedRegion(saved, text)` (common prefix and suffix, a BOM removed from the old text; a file that is not on disk yet is all new), and `planNoteTags(..., region)` tags **only the notes the region reaches** (an entry whose span `[heading, end of text]` touches it, the ends included; the text before the first heading when it is touched; a file without entries is one note). A note is skipped when the region lies **inside its own tag line** (a tag the user took away, or a line edited by hand, is not put back). Two changes far apart make one stretch that covers the entries between them (they are tagged only if their own text earns tags). Edits are `vscode.TextEdit.replace`; a failure is logged and the save goes on without edits. `onDidTagOnSave` makes `taggingCommands.ts` show `Saved <file> with tags: #…` in the status bar. It uses every keyword and every pattern, like Run Tagging.
- **Manage categories and tags**: the command `noteRoot.manageLabels` runs `labelCommands.ts`. It is in the Command Palette only (it was in the `...` menu of the Quick Note view, removed; the Tags & Categories view and page do the same) and has no title bar button. The `$(tag)` icon is still declared on the command. It shows a `createQuickPick` with separators (Categories, Tags), one row per entry with item buttons (change file, rename, delete; tags have no file button) and the two create rows. Picking a row instead of a button gives a menu with the same actions. Every action closes the list, runs, and the list opens again with the new state, until the user closes it; an error (for example a locked config file) is reported once and ends the loop. The questions are in `labelDialogs.ts` and shared with the Quick Note view (`askNewLabel`, `askNewName`, `askCategoryFile`). `LabelService.rename` keeps every other field of the entry and the file of a category, refuses a name that another entry has (`NameConflictError`; a change of case only is fine), and keeps the chosen entry chosen (the `LabelChange.select` payload of `onDidChange` makes the page select the new name). `LabelService.remove` removes only the name, **never the file of a category**, and clears the choice when the removed entry was chosen. Both go through `ConfigService.updateCustom`, so a damaged or newer config file is never changed.
- **Import by dropping**: `NotesDragAndDrop` also accepts drops from outside (`dropMimeTypes` has `files` and `text/uri-list`; tree-internal drops win when both are present). `readExternalSources` keeps only `file:` URIs (data from outside is not trusted). `FileOperationsService.importItems` copies with `workspace.fs.copy(..., { overwrite: false })`, never moves, and works like `moveItems` for conflicts (Replace trashes the old item first, Skip, Cancel) and failures. It skips items already inside the root and folders that contain the destination (a copy into itself), refuses a `.noteroot` name in the root, and validates every name with `NameValidator`. Drop target rules are the same as for moves.

- **Google Drive sync** (`GoogleDriveSyncProvider`, id `googledrive`, a normal `SyncProvider` in the `syncProviders` array of `extension.ts`, so it has every page, option, the encryption decorator, the diff and the conflict questions of GitHub; `canLimitHistory` is false, so there is no history row). Writing an id or a secret goes through `GoogleClientStore.update` (an empty part is allowed, because the two are typed one after the other; both empty removes the client) and signs out, because a refresh token belongs to one client. There is no command for it. Without a client of the user the constants in `src/constants/google.ts` are used, which are **empty until the developer fills them in** (`GoogleClientStore.effective` chooses: config, then local, then the constants; `GoogleAuth.client` reads it). While there is no pair, `signIn` throws `GoogleError` (`notConfigured`). Setting it up once: Google Cloud Console, new project, enable the Google Drive API, OAuth consent screen (External, scope `drive.file`, then **Publish app** to *In production*, because in *Testing* the refresh token ends after 7 days and only 100 users are allowed), create an OAuth client of type *Desktop app*, put the id and the secret in the constants. A desktop client secret is not confidential (Google ships it with every program of this kind). **How it syncs:** the hash of a file is the **MD5** that Drive reports (`md5Checksum`; a Google document has none and is skipped), the **version** has no Drive equivalent, so it is the sha256 of the sorted list of `path\tmd5` of the folder (`versionOf`), so `snapshot`, `currentVersion` and a push each read the folder with **one paginated list of everything NoteRoot made** (`listAll`, `trashed = false`, 1000 per page, at most 20 pages) and build the tree under the target folder from the parents (`read`; a name with `/`, a name twice in one folder (the first by id wins) and a Google document are skipped and counted in the log). `upload` reads the folder again, refuses (`conflict`) when its version is not `expectedVersion` (no expected version means the folder was empty), makes the missing folders one after the other, then creates (multipart) or updates (`uploadType=media`, which gives Drive a new version of the same file) the files four at a time and moves deleted ones to the Trash of Drive (`trashed: true`). It is **not atomic** (many requests, no lock in Drive), so two computers that push at the very same moment can mix their files; the version check right before the push makes that unlikely. `download` checks the MD5 of the bytes against the hash the sync expects. Errors are `GoogleError` (`src/util/errors.ts`, friendly texts in `Strings.sync.googleDrive`, the status code kept). Nothing from a note, no token and no code is logged. Needs a local window (the browser and the loopback server must be on the same machine as the extension host). Changed notes are read and sealed in memory before the upload. `tools/decrypt-repo.js` (Node alone) and `tools/decrypt-repo.ps1` (Windows PowerShell 5.1 or 7, scrypt and AES-GCM in C# inside the script, the key made once) are not shipped, open a cloned repository, and must stay in step with `SyncCrypto.ts` (same layout, scrypt parameters and authenticated data). **Only the chosen files (custom):** the header has `custom: true` and the stored `encryption` has `custom`; `connect` (empty target) and `encryptRepository` ask `askScope` (every note / only the chosen). The user's list is the folder-only setting `encryptPatterns` (`custom.folderSettings.encryptPatterns`, same syntax as the hidden list, default empty, row in group Notes), read by a third `ExcludeMatcher` (`encryptMatcher` in `extension.ts`, last constructor argument of `SyncService` and of `NotesTreeProvider`); `SyncService.isSealedPath(path)` checks every segment like `isExcludedFromTagging`; `providerOf` passes `isSealedPath` to `EncryptionSupport.wrap(provider, config, isSealed)` only when `custom` is set, and **without a rule everything is sealed** (the safe side). A note that is not chosen is online **as it is, at its own path**, and its index entry is `{ name: <path>, hash, plain: true }` (the hash is still the sha256 of the content and is checked on download); the index stays sealed, so only the file list of the plain notes is visible. `EncryptedSyncProvider.upload` stores each changed note in the form `wantsSeal` says and **also re-sends every note whose entry no longer matches the rule** (read from the remote, even if its content did not change), deleting the file it had in the other form; this runs only inside a push, so "Encrypt in Sync" takes effect at the next Push that has something to send. `rewrite` takes `isSealed` (`custom` = it is present). Commands `noteRoot.encryptInSync` / `noteRoot.dontEncryptInSync` (`encryptListCommands.ts`, tree menu group `6_exclude@3`, with Hide from NoteRoot and Don't Auto-Tag, always shown, so the list can be filled before the sync is set up (the context key `noteRoot.syncCustom` is still published); `NoteItem.sealed` and the context suffix `.sealed`, tested with a negative lookahead like `.notag`; the generic `addToPatternList` / `removeFromPatternList`). `tools/decrypt-repo.js` and `.ps1` read `plain` entries. **Marks:** `SyncService.sealOf(change)` (one rule for the Sync page and the push question) says what happens to a changed file that is sent: `encrypted` (the target is encrypted and either every note is or the list chooses it), `listed-plain` (on the list while the target is not encrypted: it would go online readable) or null (deleted files have none); the rows of the Changes section of the Sync page show a badge (green, or the warning colour for `listed-plain`). The Encryption section of the page lists the notes of the folder that the list chooses (`SyncPageProvider.readEncryptedFiles`, `walkFiles` with `isSealedPath`, at most `MAX_ENCRYPTED_FILES` = 200, read `FILES_DELAY_MS` after the last change of the files or of the list, so the page gets them in a second `update`), under *Notes that are encrypted* for a repository that encrypts the chosen files, or *Notes on the list (not encrypted yet)* for a plain one. **A repository that is not encrypted ignores the list**, so `runPush` in `syncCommands.ts` asks first when a file to push is on the list (`SyncService.isSealedPath`, `Strings.sync.markedNotEncrypted`): a modal that names up to five of the files with **three choices** and Cancel: **Push as Plain Text** (as before); **Encrypt the Marked Files, Then Push** (`encryptRepositoryFlow(connection, "chosen")`, the same questions as the Encrypt Repository command except the scope: confirm, names, older versions, master key; the target becomes "only the chosen files", an empty target is just set up with `prepareEncryption` + `connect`, and then `runPush` starts again with an encrypted target); **Leave Them Out of This Push** (`SyncService.push(message, { skip })`: the files are not sent and stay as local changes, the base keeps their old state; if nothing else is left it says there is nothing to push). Deleted files are not asked about. **The setting `syncMarkedAction`** (folder-only, `encrypt` by default; `plain`, `skip`, `encrypt` answer for the user; row "A marked file in a plain repository" in the Sync & Encryption group of the Settings page, and an option of the **Encryption** section of the Sync page (in both states, not in Options), which runs `noteRoot.syncMarkedAction`, a QuickPick that writes the setting) decides whether the modal is shown: `runPush` takes the answer from `SettingsService.syncMarkedAction` unless it is `ask`. Checked with a throwaway harness (fake provider: sealed and plain notes, a rule that changes, tampering, `rewrite`, no rule). **Key tools:** `SyncService.encryptRepository({ names, custom, masterKey, dropHistory })` (plain target only: downloads every synced file, `EncryptionSupport.rewrite` seals all of them under a new salt/key and sends them, the header, the index and the removal of the plain names as ONE upload), `changeMasterKey({ masterKey, dropHistory })` (`EncryptionSupport.readEverything` opens every note, asking the old key when it is not kept, then `rewrite` with a new salt and removes the old sealed names; the old saved key is deleted) and `forgetKey()` (`EncryptionSupport.forgetKey` + dropping the wrapper cache); `dropHistory` is `upload(..., { keepLast: 1 })`, the user's explicit choice (`askDropHistory`). `adoptEncryption` stores the new `encryption` config and the new base from the hashes just sent. The new key is kept on this computer only after the upload worked. **Change the file names** (`noteRoot.syncChangeNames`, the **Change…** of the File names row of the Sync page and the palette while the target is encrypted): `askNameMode` (kept or hidden; the same as now only says so), the confirmation, the question about the older versions (they keep the old names unless the history is dropped), the master key twice (the same key keeps it, a new one changes it), then `SyncService.changeMasterKey({ masterKey, dropHistory, names })`, which seals everything again with the new naming (the plain notes of the chosen-files mode are not touched, the old sealed names go away). Commands `noteRoot.syncEncryptRepository` (shown while `noteRoot.syncEncrypted` is false), `syncChangeKey` and `syncForgetKey` (while it is true); `publishConnected` sets the context key. Not done: other computers are not told about a key change (they fail with a wrong key until the user connects again), and the older commits keep the old content unless the history is dropped. The logic was checked with a throwaway harness (the real `SyncService` against a fake GitHub with several computers, the commands with scripted answers, a second provider on a shared folder, and the encrypted sync including tampering and wrong keys); the real GitHub and the view need F5.
- **State**: tree state and drafts in `globalState`, debounced 300 ms. Nothing is written into the notes folder except `.noteroot/config.json` and the notes.

## Decisions that differ from the original design

- The Quick Note button says **Save**, not OK (`Strings.quickNote.okLabel`).
- The general actions are plain commands in `...` menus (`view/title`, no icon). The **Notes** view keeps four: Undo Last Rename or Move (`1_edit@1`), Change Notes Folder, Reveal Root Folder in OS and Open Notes Folder in New Window (`2_folder@1..3`). Open Settings Page is in the same menu of the Notes view (`4_settings@1`); the config file and the logs are buttons of the Settings page. (Open Notes Folder in New Window runs `vscode.openFolder` with the root URI and `{ forceNewWindow: true }`, and offers to select a folder when there is none.) A bar at the bottom of the sidebar was tried and dropped: VS Code has no sidebar footer, so such a bar can only live inside one webview view and does not stay at the bottom of the sidebar.
- Views have `icon` set in `package.json`. `activationEvents` is empty (VS Code generates them).
- `ExcludeMatcher` is case-insensitive on every OS.
- `workspace.fs.writeFile` cannot refuse to overwrite, so creating a file or the config has a tiny race. It is documented in comments.

## Gotchas

- Names: ids `noteRoot.*`, config folder `.noteroot`, package `noteroot`, encrypted header `NOTEROOT-ENCRYPTED v1`, GitHub repository `talakbairam/NoteRoot`.
- In the Windows Bash tool, heredocs and `sed` mangle backslashes. Write JSON, regexes and Windows paths with the Write or Edit tool, or use forward slashes. In `package.json`, `when` clauses need `\\.` in regexes.
- `.vscodeignore` ships only `dist/extension.js`, `media/**`, `webview/**`, README, CHANGELOG, LICENSE and `package.json`. Check with `npx vsce ls`.
- `when` clauses of `package.json` have `=~` but **no `!~`**. To say "does not contain" use a regex with a negative lookahead (`viewItem =~ /^noteRoot\.file(?!.*\.hidden)/`) so each pair of entries (Exclude / Include) is exclusive.
- Update `README.md`, `CHANGELOG.md` and this file when behaviour changes.
